# Remote FPGA Hardware-in-the-Loop (HIL) Programming

A PC-to-Raspberry Pi-to-FPGA workflow for remotely operating an FPGA-based Arithmetic Logic Shift Unit (ALSU) and uploading a bitstream over a local network. The project combines a Python desktop GUI, a TCP server on the Raspberry Pi, UART communication, and VHDL logic for a Basys 3 FPGA.

> **Validation note:** The Python protocol/validation tests can be run locally. Physical Raspberry Pi + Basys 3 operation must be verified on the actual hardware and board setup; this repository does not claim that a hardware run was performed as part of this upload.

## Architecture

```text
PC GUI (CustomTkinter)
       │ TCP: length-prefixed JSON, port 5000
       ▼
Raspberry Pi server (pi_server/server.py)
       ├── Bitstream upload → openFPGALoader → FPGA configuration
       └── ALSU operation → UART at 115200 baud
                                      │
                                      ▼
                         Basys 3 FPGA (VHDL)
                         ├── UART_RX / UART_TX
                         ├── HIL_Controller FSM
                         └── Combinational ALSU_Core
                                      │
                                      └── 16-bit result returned to GUI
```

## Features

- PC desktop GUI for connecting to a Raspberry Pi server.
- Input validation for operations and 8-bit operands.
- Network messages framed with a 4-byte big-endian payload length and UTF-8 JSON.
- ALSU operations: addition, subtraction, multiplication, left shift, bypass A, and bitwise XOR.
- Bitstream upload over TCP and programming through `openFPGALoader` on the Raspberry Pi.
- VHDL modules for the combinational ALSU, UART receive/transmit, and top-level HIL controller.
- Unit tests for the TCP message format and GUI input validation.

## Hardware and interfaces

- **FPGA board:** Digilent Basys 3 (Artix-7)
- **Clock:** 100 MHz system clock on package pin W5
- **UART baud rate:** 115200 bps; UART modules default to 868 clock cycles per bit
- **Pmod JA / Raspberry Pi UART wiring:**
  - FPGA RX, package pin J1 (JA1) ← Raspberry Pi TXD, GPIO 14
  - FPGA TX, package pin L2 (JA2) → Raspberry Pi RXD, GPIO 15
  - Connect the grounds together and use compatible 3.3 V UART logic levels.
- **ALSU result width:** 16 bits. The FPGA UART returns the high byte first, followed by the low byte.

Check the exact pin map and serial device name on your own hardware before powering or programming the board.

## Run the PC GUI (Windows)

Python 3.10 or newer is recommended.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements_pc.txt
.\.venv\Scripts\python.exe -m pc_gui.main
```

In the GUI, enter the Raspberry Pi's LAN IP address and server port (default `5000`), connect, select an ALSU operation and operands, or choose a `.bit` file to upload.

## Run the Raspberry Pi server

Install the Python dependencies on the Pi:

```bash
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements_pi.txt
```

Install `openFPGALoader` using a supported package/build for the Raspberry Pi OS and connect the FPGA using the configured UART interface. Then start the server from the project root:

```bash
python -m pi_server.server --host 0.0.0.0 --port 5000 --uart-port /dev/ttyAMA0 --baud 115200
```

Use the serial device that corresponds to your actual GPIO UART. Raspberry Pi serial-console configuration can occupy the UART and may need to be adjusted. Verify permissions for the serial device and `openFPGALoader` before testing.

## UART protocol

The included VHDL `HIL_Controller` expects each ALSU request as exactly three UART bytes:

1. Operand A (0–255)
2. Operand B (0–255; for SHIFT, use 0–7)
3. Opcode in the low three bits: ADD=`000`, SUB=`001`, MUL=`010`, SHIFT=`011`, BYPASS=`100`, XOR=`101`

It sends a 16-bit result as two bytes in big-endian order (high byte first, low byte second). `pi_server/fpga_bridge.py` uses this byte format.

The PC-to-Pi network protocol is separate: a 4-byte big-endian message length followed by a JSON object. Supported message headers are `PING`, `ALSU`, and `FILE`.

## Tests

From the project root, install PC requirements and run:

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

The tests do not replace hardware validation. A full system test should verify UART pin routing, opcode behavior, response byte order, network connection, and bitstream programming on the actual board.

## Security note

The Pi server listens on all interfaces by default and accepts bitstream-upload requests. Run it only on a trusted LAN, restrict access with firewall rules, and **do not expose port 5000 directly to the public internet**. This project does not implement authentication or encrypted transport.

## Limitations

- FPGA bitstream programming depends on a compatible `openFPGALoader` installation, cable/board access, and local permissions.
- The 16-bit ALSU result uses unsigned bit patterns; subtraction underflow follows the VHDL result width.
- Network and hardware behavior should be measured on the intended PC, Raspberry Pi OS, serial adapter/GPIO connection, and Basys 3 setup.
